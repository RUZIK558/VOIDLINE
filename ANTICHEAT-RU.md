# VSAC / VCAC — модель защиты и эксплуатация

## Что доверено
Сервер единолично изменяет координаты, физику, здоровье, деньги, боезапас, попадания, урон, время выстрелов, задержки оружия и состояние бомбы. Клиент передаёт управляющие намерения, не результаты. VSAC — дополнительная граница проверки перед существующей авторитетной игровой логикой.

## VSAC
Пакеты WebSocket ограничены 16 КиБ; на входе — ограниченная сложность JSON, строгие верхнеуровневые поля команд, проверка чисел и типов. Token bucket допускает обычные 60 input/с и короткие всплески от клавиатуры/мыши. Трафик сверх бюджета отклоняется; постоянный спам/невалидный протокол набирает затухающий счёт и приводит к закрытию соединения (1008). Ошибки тайминга сами по себе не являются основанием постоянного бана. События не содержат полного содержимого пакетов, приватных токенов resume, IP или HWID; хранится ограниченное число записей.

Новый клиент объявляет протокол 1 и нумерует input в пределах каждого соединения. Не возрастающий seq отклоняется. Счётчик начинается заново только в новом соединении. Для совместимости старые клиенты без объявления протокола по умолчанию допускаются, но всё равно проходят проверку полей/типов/трафика; защита от replay input для них не заявляется. Чтобы запретить старый протокол на выделенном сервере:

```bash
VOIDLINE_VSAC_STRICT=1 npm run server
```

Это требование версии протокола, НЕ доказательство неизменённого клиента. Свежий nonce и счётчик отчётов предотвращают простое повторное использование записанного отчёта в другом соединении; атакующий, контролирующий клиент, всё равно может сформировать новый отчёт. Отсутствие отчёта/сообщение клиента о модификации пишется в диагностику, а не используется как доказательство для бана. Поведение при лаге и потере соединения остаётся прежним; после отключения ввод сбрасывается.

В Electron события VSAC пишутся в вращаемый diagnostics.log владельца. У выделенного сервера они выводятся как JSON со строкой [VSAC]. Панель владельца показывает счётчики. Обычному сетевому клиенту управление сервером не предоставляется.

## VCAC
Манифест генерируется во время `npm run dist` после сборки поставляемого помощника ввода; добавление файлов не требует доступа к чужим каталогам. Пакетный package.json хешируется по стабильным исполняемым полям (main/type/name/version/dependencies), поскольку упаковщик удаляет build/scripts/devDependencies. Остальные перечисленные файлы проверяются побайтово.

Установленный клиент проверяет файлы перед запуском интерфейса и раз в 60 секунд. В пределах проверки отсутствуют произвольные внешние пути; выход через .., неизвестные каталоги и ссылки за пределы приложения отклоняется. Для собственного ASAR-unpacked помощника разрешён только соответствующий каталог приложения. Через preload предоставляется только текущий статус. Проверка работает без сети, без фоновой службы после закрытия игры, без административных прав и драйвера.

## Чего эта версия не обещает
- Сам манифест и исполняемый файл не образуют доверенную аппаратную/удалённую аттестацию. Переписав основной процесс вместе с манифестом, атакующий может обойти VCAC. Для более сильной цепочки нужны подпись релиза, защищённая доставка и проверяемая платформа; в этой сборке они не реализованы.
- Клиентские отчёты, метки таймингов и отсутствие отклонений — не доказательство честности.
- Не реализовано обнаружение всех aimbot/ESP/макросов, сканирование памяти/процессов, ядровая защита, HWID-баны, облачный список банов или внешняя DDoS-защита. Серверные snapshots пока передают позиции игроков; полная anti-ESP-система с фильтрацией видимости требует отдельной реализации.
- Старые клиенты доступны только ради совместимости; для новых закрытых матчей рекомендуется строгий протокол и одинаковая версия у всех участников.
- Постоянные санкции не выдаются автоматически: требуется независимая проверка доказательств. Сведения о профиле и личных файлах не собираются.

VSAC/VCAC реализованы в JavaScript/Node.js: это позволяет выполнять проверки рядом с авторитетной логикой и читать ASAR через Electron без дополнительного Python/Rust-рантайма. Сам по себе выбор Rust не сделал бы клиент доверенным на компьютере атакующего.
