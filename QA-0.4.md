# Проверки VOIDLINE 0.4

## Автоматические проверки

`npm test`: **28 passed, 0 failed, 0 skipped**. Сетевые сценарии прогоняются с реальными таймерами; длинные переходы матча дополнительно проверяются на синтетических часах.

- Коллизии карты, пересечения лучей, ускорение/торможение, контр-стрейф, ограничение диагональной скорости, скорость приседания.
- Серверная высота приседания; независимые объёмы головы/корпуса/ног; жилет, шлем, исчерпание брони, реальные выстрелы и блокировка стенами.
- Разброс/паттерн, полуавтоматический пистолет, магазин/резерв/перезарядка.
- Покупка по фазе/деньгам/зоне/команде, защита от поддельных имён предметов и оружия; некорректные числовые значения и имена клиента.
- Выброс, подбор, сохранение патронов, отсутствие дубликатов, ограничение дальности и преград, оружие после смерти.
- Установка на правильной точке только своим носителем, непрерывное удержание, отмена действий, одно активное разминирование, набор, истечение ввода.
- Взрыв, урон, гибель всей атаки после установки, приоритет истёкшего взрыва над поздним разминированием, тайм-аут защиты.
- Передача бомбы после смерти/отключения, выплаты, сохранение экипировки выживших, сброс экипировки умерших, смена сторон и сброс экономики, завершение матча и явный restart.
- Поздний вход наблюдателя без ложной победы, хост, добавление/удаление ботов, ограничения команд, LAN на том же матче, занятый порт, закрытие LAN без отключения хозяина, отклонение сетевых host-команд.
- Реальные TLS P2P-пиры: закреплённые приглашения, обмен сообщениями, ACK, сохранение истории.

### Реальные WebSocket-сценарии

1. Два подключения: закупка → выброс → подбор → движение через карту → установка → взрыв → выплата → закупка винтовки в следующем раунде → restart.
2. Два подключения: защита покупает набор, обе стороны идут к точке; установка → начало/отмена разминирования → успешное разминирование с набором.
3. Бот: человек роняет бомбу → бот сам подбирает → обходит укрытия → устанавливает → взрыв.

Маршруты выполнялись серверным движением через WebSocket, без изменения координат напрямую. Для сокращения времени этих тестов используются укороченные таймеры, переданные в серверную функцию `startServer`; клиент изменить их не может. Полный цикл смены сторон и завершения матча проверяется модульно на синтетических часах.

## Клиент

Локальный Chromium / WebGL через программный SwiftShader, 1440×900:

- Подключение, открытие B, покупка брони и изменение денег/брони в HUD.
- Закрытие закупки, переход в бой, ввод приседания.
- Выбрасывание пистолета, состояние «без оружия», подбор через E.
- Во время этого завершённого сценария JavaScript page errors отсутствовали.
- Скриншоты `previews/04-buy.png` и `previews/04-game.png`.

Дополнительный двухоконный браузерный прогон остановился по тайм-ауту на вводе приседания. Визуальное отображение удалённого приседания этим прогоном не подтверждено; сетевые свойства и серверная высота проверены отдельно.

Это функциональная проверка, не замер FPS и не проверка драйверов/аудиоустройства на пользовательском компьютере.

## Упаковка и ограничения проверки

Сборочные цели: Windows x64 portable и Linux x86_64 AppImage. Обе сборки app.asar проверены: все шесть игровых файлов совпадают с текущими исходниками. Извлечённый из Linux app.asar сервер успешно запущен в Node: проверены HTTP-ресурсы и реальный WebSocket-вход с переходом в бой. Это не запуск оболочки Electron. SHA-256 готовых файлов вынесен в файл контрольных сумм.

**Не подтверждено:** полноценный desktop-запуск готового Windows EXE и Linux AppImage на целевых ОС; работа на конкретном GPU, FUSE/GTK на машине пользователя; 10 человек на физической LAN; игра через публичный интернет; поведение при больших задержках/потерях пакетов; античит или независимый аудит безопасности. Нет Windows runtime и полноценной Linux desktop-сессии для такой проверки. Сборки не подписаны.
